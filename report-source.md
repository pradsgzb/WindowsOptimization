# Windows 10/11 Performance Optimization Script - Research Source

Audience: Windows 10/11 workstation owners and administrators  
Research date: 2026-09-07  
Scope: Supported, reversible where practical, performance and disk-maintenance actions suitable for a general Windows client workstation. The implementation must remain safe enough for managed business endpoints and must not weaken endpoint security.

## Direct answer

A trustworthy Windows optimization script should automate a narrow set of documented controls, inventory the system before changing it, and ask for informed consent. It should not apply the broad service-deactivation, registry, networking, security, or memory folklore common in online “debloat” scripts. Windows already performs several maintenance operations automatically, so the script must distinguish an available action from an action that will produce a measurable improvement on a specific PC.

## Scope assumptions

- Windows client only (Windows 10 or Windows 11), not Windows Server.
- 64-bit Windows 10/11 client and 64-bit Windows PowerShell 5.1 Desktop for Apply/Restore.
- Changes are local and require elevation; domain-managed devices require an explicit override.
- Interactive consent uses Y/N/A, with A limited to the current category.
- Temporary-folder cleanup confirms once per folder, never once per file, skips reparse points, preserves the folder itself, and defaults to files at least seven days old.
- Rollback restores stateful configuration changes. Deleted cache/temp data, component cleanup, and volume optimization are inherently not restorable from the JSON backup.

## Evidence and implementation consequences

1. Microsoft’s current performance guidance prioritizes Windows Update, restart, free disk space, startup-app review, visual-effects reduction, power mode, malware checks, and pausing OneDrive sync when appropriate. Implementation: cover the automatable and supported subset and open the official Settings/UI for decisions that lack a stable public automation interface. Source: “Tips to improve PC performance in Windows,” Microsoft Support, accessed 2026-09-07, https://support.microsoft.com/en-us/windows/experience/performance-optimization/tips-to-improve-pc-performance-in-windows

2. Storage Sense is Microsoft’s supported facility for automatically removing temporary files and Recycle Bin contents. Implementation: provide a Storage Sense review shortcut and offer controlled cleanup only for the two well-known Temp roots; do not manually empty Windows Update, Prefetch, browser, or application-specific caches. Sources: “Free up drive space in Windows,” Microsoft Support, accessed 2026-09-07, https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/free-up-drive-space-in-windows ; “Manage drive space with Storage Sense,” Microsoft Support, accessed 2026-09-07, https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/manage-drive-space-with-storage-sense

3. `Delete-DeliveryOptimizationCache` is the documented cmdlet for clearing Delivery Optimization cache state. Delivery Optimization already manages its cache quota automatically. Implementation: make cache clearing opt-in and use the cmdlet instead of deleting its backing folders. Sources: “Monitor Delivery Optimization,” Microsoft Learn, updated 2026-05-20, https://learn.microsoft.com/en-us/windows/deployment/do/waas-delivery-optimization-monitor ; “Delivery Optimization reference,” Microsoft Learn, updated 2026-05-21, https://learn.microsoft.com/en-us/windows/deployment/do/waas-delivery-optimization-reference

4. `DISM /Online /Cleanup-Image /StartComponentCleanup` is documented for component-store cleanup. `/ResetBase` prevents installed updates from being uninstalled. Implementation: expose `StartComponentCleanup` only and explicitly prohibit `/ResetBase`. Source: “Clean Up the WinSxS Folder,” Microsoft Learn, updated 2025-03-10, https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/clean-up-the-winsxs-folder?view=windows-11

5. `Optimize-Volume` chooses an operation appropriate to the drive type when no operation parameter is supplied (including defragmentation or retrim). Implementation: use the cmdlet’s default operation only for healthy, fixed NTFS/ReFS volumes and do not force HDD-style defragmentation on SSDs. Source: “Optimize-Volume,” Microsoft Learn, accessed 2026-09-07, https://learn.microsoft.com/en-us/powershell/module/storage/optimize-volume

6. TCP receive-window auto-tuning set to Normal is Microsoft’s documented remediation for throughput problems caused by disabled/restricted auto-tuning. Implementation: offer a normalization action only when one or more TCP templates are non-Normal, record each prior value, and avoid Nagle/MTU/offload/DNS registry guesses. Source: “TCP/IP performance known issues,” Microsoft Learn, updated 2026-02-12, https://learn.microsoft.com/en-us/troubleshoot/windows-server/networking/tcpip-performance-known-issues

7. Receive Side Scaling distributes receive processing across CPUs and can improve throughput; enabling it restarts the adapter and can briefly interrupt connectivity. Implementation: make it opt-in, target only present physical adapters that report RSS support, disclose the interruption, and record prior state. Sources: “Enable-NetAdapterRss,” Microsoft Learn, accessed 2026-09-07, https://learn.microsoft.com/en-us/powershell/module/netadapter/enable-netadapterrss ; “Introduction to Receive Side Scaling,” Microsoft Learn, updated 2025-11-05, https://learn.microsoft.com/en-us/windows-hardware/drivers/network/introduction-to-receive-side-scaling

8. Best performance power mode can improve responsiveness but increases power consumption and heat. Windows 11 exposes a documented current-user AC power-mode API; `powercfg /setactive` is the documented interface for activating an existing Windows 10 plan. Implementation: change only the Windows 11 AC vote, or activate the existing Windows 10 High performance plan without creating one. On a battery-equipped Windows 10 device, require verified AC power and a dedicated acknowledgement because the plan also supplies its DC settings. Sources: “Tips to improve PC performance in Windows,” Microsoft Support, accessed 2026-09-07, https://support.microsoft.com/en-us/windows/experience/performance-optimization/tips-to-improve-pc-performance-in-windows ; “PowerSetUserConfiguredACPowerMode,” Microsoft Learn, updated 2025-02-28, https://learn.microsoft.com/en-us/windows/win32/api/powrprof/nf-powrprof-powersetuserconfiguredacpowermode ; “Powercfg command-line options,” Microsoft Learn, 2021-12-15, https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/powercfg-command-line-options ; “PowerSetActiveScheme,” Microsoft Learn, https://learn.microsoft.com/en-us/windows/win32/api/powersetting/nf-powersetting-powersetactivescheme

9. Client-area animations can be changed through the documented `SystemParametersInfo` API. Implementation: use the API, not an undocumented registry blob, and save the old Boolean state. Sources: “SystemParametersInfo function,” Microsoft Learn, updated 2024-03-27, https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfoa ; “Client area animation parameter,” Microsoft Learn, updated 2025-07-14, https://learn.microsoft.com/en-us/windows/win32/winauto/client-area-animation

10. Task Manager exposes startup-app impact and lets the user disable entries. Implementation: inventory startup commands and open the supported Startup Apps UI; do not manipulate the opaque StartupApproved registry data. Sources: “Startup apps,” Microsoft Learn, updated 2020-09-10, https://learn.microsoft.com/en-us/windows/win32/w8cookbook/startup-apps ; “Tips to improve PC performance in Windows,” Microsoft Support.

11. `Win32_Service` exposes the configured executable, account, service type, state, and start mode. Shared services can be hosted by `svchost.exe` and implemented by a ServiceDll. Implementation: a name match is insufficient—before every service mutation, verify the current executable and ServiceDll as valid Microsoft OS binaries in approved paths, bind the stable path/account/type mapping into rollback, and re-fingerprint immediately after consent. Sources: “Win32_Service class,” Microsoft Learn, accessed 2026-09-07, https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-service ; “Service host grouping in Windows 10,” Microsoft Learn, https://learn.microsoft.com/en-us/windows/application-management/svchost-service-refactoring ; “Get-AuthenticodeSignature,” Microsoft Learn / PowerShell 5.1, https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/get-authenticodesignature?view=powershell-5.1 ; “Signature class,” Microsoft Learn, https://learn.microsoft.com/en-us/dotnet/api/system.management.automation.signature

12. Windows per-user services can have a generated suffix and disabling a template can break dependent applications. Implementation: exclude suffixed per-user services and avoid wildcard service modifications. Source: “Per-user services in Windows,” Microsoft Learn, updated 2024-10-01, https://learn.microsoft.com/en-us/windows/application-management/per-user-services-in-windows

13. Restore points are supported on Windows client and `Checkpoint-Computer` permits only one checkpoint per day. Implementation: attempt one best-effort restore point before apply unless skipped, but retain a separate JSON configuration backup because restore points are not guaranteed and do not restore deleted temporary data. Source: “Checkpoint-Computer,” Microsoft Learn / PowerShell 5.1, accessed 2026-09-07, https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/checkpoint-computer?view=powershell-5.1

14. Windows 10 Home/Pro 22H2 reached end of support on 2025-10-14; LTSC and ESU have separate lifecycles. Implementation: remain technically compatible but emit a prominent support warning rather than presenting optimization as a substitute for supported security updates. Sources: “Windows 10 Home and Pro,” Microsoft Lifecycle, accessed 2026-09-07, https://learn.microsoft.com/en-us/lifecycle/products/windows-10-home-and-pro ; “Extended Security Updates program for Windows 10,” Microsoft Learn, updated 2025-11-17, https://learn.microsoft.com/en-us/windows/whats-new/extended-security-updates

15. Microsoft generally does not recommend disabling or uninstalling Defender Antivirus, and system-managed page files respond to commit pressure. Implementation: never disable Defender, firewall, Windows Update, BITS, Event Log, cryptographic services, page files, memory compression, or other security/servicing foundations. Sources: “Microsoft Defender Antivirus in Windows Overview,” Microsoft Learn, updated 2026-03-25, https://learn.microsoft.com/en-us/defender-endpoint/microsoft-defender-antivirus-windows ; “Introduction to the page file,” Microsoft Learn, updated 2026-02-12, https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/introduction-to-the-page-file

16. Trigger-start services can remain stopped until a trigger occurs, avoiding a permanent polling process. Microsoft also warns that service-disable guidance is configuration-specific. Implementation: leave Manual-and-Stopped services unchanged unless the operator explicitly supplies `-DisableDemandStartServices`; no service is Recommended, and “A” remains scoped by category and risk. Sources: “Service Trigger Events,” Microsoft Learn, https://learn.microsoft.com/en-us/windows/win32/services/service-trigger-events ; “Guidance on disabling system services on Windows IoT Enterprise,” Microsoft Learn, updated 2026-06-24, https://learn.microsoft.com/en-us/windows/iot/iot-enterprise/optimize/services

17. `GetSystemPowerStatus` reports AC-line and battery status through a documented Win32 API. Implementation: component-store and volume maintenance fail closed on a battery-equipped device unless it is verifiably on AC; Windows 10 power-plan changes use the same live gate. Source: “GetSystemPowerStatus,” Microsoft Learn, https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getsystempowerstatus

18. Windows service defaults are build/edition/role dependent, and Microsoft’s complete disable table is aimed at fixed-function IoT Enterprise systems. Implementation: treat that table as candidate discovery, not authority to disable a service on a general workstation. Detect the installed service live, show its exact verified identity and consequence, and fail closed on unknown variants. Source: “Guidance on disabling system services on Windows IoT Enterprise,” Microsoft Learn, updated 2026-06-24, https://learn.microsoft.com/en-us/windows/iot/iot-enterprise/optimize/services

19. The public `ShouldProcess` model underlies `-WhatIf` and `-Confirm`. Implementation: every OS mutation passes through ShouldProcess in addition to the requested Y/N/A decision; Apply WhatIf creates no rollback manifest/key because no selected operation may mutate Windows. Source: “Everything about ShouldProcess,” Microsoft Learn, https://learn.microsoft.com/en-us/powershell/scripting/learn/deep-dives/everything-about-shouldprocess

20. Windows binaries may legitimately change during monthly servicing. Implementation: keep stable service mapping (name, executable/ServiceDll path, account SID, registry type) separate from file hashes/certificate evidence. Restore never crosses a changed mapping, while a still-valid Microsoft servicing fingerprint drift requires the dedicated `-AcknowledgeServicedServiceIdentityDrift` switch and is fully displayed before consent.

21. `WTSQuerySessionInformation` retrieves information for a specific local session, including its user and domain, and requires its returned buffer to be released with `WTSFreeMemory`. Implementation: resolve the owner SID of the current process session and require it to match the elevated token SID before any user-scoped cleanup, power, animation, or Settings action; over-the-shoulder elevation with a different administrator fails closed. Source: “WTSQuerySessionInformation function,” Microsoft Learn, updated 2023-02-09, https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/nf-wtsapi32-wtsquerysessioninformationw

## Material limitations

- No generic script can guarantee a speed increase. A PC limited by failing storage, insufficient RAM, thermal throttling, malware, driver faults, or a specific application needs diagnosis rather than more tuning.
- Microsoft service-disable guidance for IoT/VDI/Windows Server does not automatically transfer to a general interactive Windows client. Optional client services therefore remain individually consented and are never part of the recommended unattended preset.
- A service that is Manual and Stopped consumes essentially no current CPU time; disabling it may deliver no measurable gain.
- Volume optimization and component cleanup are normally maintained by Windows. Manual invocation is primarily for remediation or low-space scenarios.
- Changing RSS can interrupt the network adapter. Do not run it in a remote session unless an outage and reconnection are acceptable.
- Microsoft OS-binary signature validation reduces the risk of disabling an OEM-repurposed or replaced service, but it cannot cryptographically prove that every signed Microsoft DLL semantically belongs to a particular service name. Every service therefore remains opt-in and must be compatibility-tested on the exact Windows builds in scope.
- The implementation is statically reviewed in this environment. Its supplied Pester/native integration release gate must still be run on representative Windows 10/11/LTSC test images before production deployment.
